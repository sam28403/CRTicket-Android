# 新旧车号对比

本功能将在未来版本移除，具体移除版本待定。

## 数据

使用用户提供的 `trainPrefix.cc6215b.js`，仅提取数据数组，不执行文件代码，也不纳入其示例和页面说明。
源文件 SHA-256：`f2664b6ea160d0dc786cd99e38b48b0ee54f6f3edbde2fc421780b1048bea3e3`。
本地资源 `app/src/main/assets/train-number-comparison.json` 共 1640 条记录，每行依次为原车号、起点、终点、新车号。
记录、新车号、原车号各自无重复。本功能展示给定数据的对应关系，不推断实施日期或实时运行状态。

## 交互与性能

首页原有查询组内，入口紧接起售时间查询，进入二级页面。
卡片复用车次列表，主车号显示新编号，右上角仅显示原车号编号，不添加“原车号”文字；不显示历时、里程、均速。
按新编号 Z、N、V 排序，同前缀按数字升序排列。
搜索支持四位纯数字，或 Z/T/K/N/V 加一至四位数字，小写自动转大写。
编辑时允许空值和单个前缀，非法输入通过 Toast 提示并拒绝；提交空值或单前缀也 Toast 提示。
新旧车号精确匹配，找不到时 Toast 提示；成功时隐藏键盘、强调色高亮并动画滚动到首个匹配项。
如未来数据出现新旧车号交叉重名，将高亮所有匹配记录并定位第一条。

本地读取、解析、排序及双向索引在 IO 调度器完成；搜索使用索引，无需遍历列表。
列表使用 LazyVerticalGrid，按最小 320dp 卡片宽度自适应列数，手机单列，平板及大屏按可用宽度展示多列。
仅组合可见卡片，固定 contentType 和稳定键；连续查询取消上一段滚动任务。
搜索栏固定在列表上方，不随结果列表滚动。
列表右侧复用车次列表的快速滚动条，按当前列数换算滚动位置。拖动范围从结果列表顶部到末尾。

## 验证

JVM 测试覆盖输入边界、大小写、数字排序、新旧双向匹配、交叉重名和未命中。
设备测试覆盖跨前缀长距离定位、新旧车号查询、选中状态、离屏卡片回收及非法输入拒绝。
构建和测试日志存放于 `logs/train-comparison-*`。

- Debug Kotlin 编译和 202 项 JVM 测试通过（含本功能 2 项）。
- CI 应用和 CI instrumentation 测试包构建通过。
