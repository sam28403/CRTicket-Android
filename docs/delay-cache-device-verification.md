# 正晚点缓存真机验证

日期：2026-10-26。设备：Pixel 8 Pro。

安装当前源码构建的 debug APK 和 androidTest APK，运行
`cc.samlab.ticket.DelayCacheDeviceTest`，最终结果为 `OK (2 tests)`，耗时 21.468 秒。

测试在手机的实际 WebView 和原生 Compose 页面中执行，使用仅随 androidTest 打包的
接口夹具提供时刻表及正晚点响应，不修改生产接口、不关闭手机网络。
夹具随测试页面销毁而失效，测试后重新打开正常应用，调试版保留安装。

## 验证结果

- 车次查询：先取得到达晚点 7 分钟、出发晚点 9 分钟，再实际下拉刷新。
  刷新失败、返回无有效数据时，仍显示 `20:00 (+7')`、`20:05 (+9')`，正晚点开关保持开启。
- 车次查询：新响应仅包含到达恢复正点时，到达更新为 `19:53`，出发仍显示缓存的
  `20:05 (+9')`。
- 车站列表：实际点击刷新按钮，正晚点请求失败、返回空列表时均保留已有到发修正。
  仅到达恢复正点时更新到达，保留出发晚点；随后时刻表刷新失败也保留该结果。
- 切换到出发大屏后，仍显示 `20:05` 和 `(+9')`。
- 已查看真机截图，车站卡片、车次停站时间和开关正常显示。

截图保存在本地 `captures/delay-cache/`。

## 验证范围

这次真机验证使用可控响应复现失败，不代表验证了 12306 当前实时接口的可用性。
北京时间午夜失效及跨午夜旧请求丢弃由前端时钟模拟回归测试覆盖，未修改手机时间验证。
