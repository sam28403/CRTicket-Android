# 铁路旅游

首页「新旧车号对比」下方进入铁路旅游。文章列表读取
`sam28403/CRTicket-Android` 仓库 `master` 分支的 `/travel`，按文件名排序。
每篇文章使用 UTF-8 编码，文件扩展名为 `.md`，列表卡片标题为去掉扩展名的文件名。
文章列表使用详情区域的全部宽度，空间充足时自动排成多列。
App 打开列表和正文时联网读取，也可使用右上角按钮刷新。联网读取失败时使用设备上最近成功读取的缓存。
文章不打包进 APK。

## 编辑文章

正文使用 Markdown。卡片标记各占一个独立段落，前后用空行分隔。

```markdown
{V23}

{V24, 二连, 北京}

{V23, 北京, 二连, 5, 771, 835}

{上海虹桥}

![站台照片](https://example.com/platform.webp)
```

车次卡片读取设备中的路路通时刻表，显示起讫站、站数、运行时间、里程和均速，点击打开路路通查询。
数据库中有记录的车次均可显示，车次号不加删除线。当天未开行的车次打开最近的开行日期。
三参数写法保留文章中写明的起讫站，本地时刻表有对应区间时按该区间计算指标。
六参数写法依次填写车次、起点、终点、站数、历时（分钟）和里程（km）。
站数和历时使用正整数，里程可使用非负小数。卡片使用文章中的数值，即使本地时刻表未收录该车次。
均速按里程除以历时（小时）计算，沿用车次列表的一位小数显示。
车站卡片采用车站大屏推荐卡片的样式和统计口径，点击打开车站大屏。
设备暂无对应时刻表数据时，卡片仍可点击，缺失数据以占位符显示。
图片建议独立成段，可使用 HTTPS 地址或仓库中相对于文章文件的路径。
正文区域居中，手机最大宽度为 400 dp，大屏最大宽度为 600 dp，图片和卡片跟随正文宽度。

## 实机验证

2026-11-20 在 Pixel 8 Pro 和 Pixel Tablet 上各通过一项端到端测试。
测试从 GitHub 读取《测试文章》及其图片，并用隔离导入的本地路路通样本校验车次和车站卡片。
核对了自适应列表、正文宽度、Markdown 标题、圆角图片、区间站数、车站统计和查询返回路径。
当天不开行的样本车次仍显示完整数据及正常车次号，点击后打开最近的开行日期。
