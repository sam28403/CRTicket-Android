# 车站大屏分段车次

路路通 `T*.dat` 保存整趟列车的完整记录号，`xw.dat` 保存分段车次。
解析时按累计里程将车次分量匹配到停站，不按车次数字、方向或站名猜测。

`xw.dat` 的数量、车次索引和里程均使用 255 进制双字节整数。
文件以记录数开头，每条记录为车次索引、两字节属性、单字节分段数，
随后每段由两字节起始里程和单字节车次分量索引组成。
分量索引按完整记录号中斜杠分隔的顺序从零开始，支持省略前缀和方案后缀。

例如实测 `20261030` 数据中的 `G100/G97`：

- 起始里程 0 使用分量 0，即 G100。
- 起始里程 1213 使用分量 1，即 G97，对应天津西。
- 南京南里程 295，显示 G100；唐山里程 1332，显示 G97。

换号站到达屏使用进入本站区段的车次，出发屏和全部信息使用离开本站区段的车次。
终到站使用到达车次。详情跳转以 `train` 传递本站展示车次，
以 `record` 单独保留完整记录号，并保留始发日期，避免同名方案混淆。
详情输入框、标题及在线请求使用所选车次，离线请求使用完整记录号。
在线、离线切换保留所选车次；用户输入无关的新车次时移除旧记录关联。
缓存同时区分所选车次和完整记录，避免不同分段或方案复用错误标题。
网页大屏和 Android 原生大屏共用此结果。

缺少分段表、文件结构损坏、分量越界、分段里程无序或停站里程不可靠时，
保留完整记录号。分段表属于可选补充数据，不使原时刻表查询失败。

验证包括分段解析回归测试、归档集成测试、车站大屏到发屏及详情跳转测试。

## 2026-10-26 实机验证

在 Pixel 8 Pro 和 Pixel Tablet 上覆盖安装调试版本，使用设备实际屏幕尺寸、
真实路路通时刻表和真实查询链路运行 `StationTrainSegmentsDeviceTest`。
两台设备最终均返回 `OK (1 test)`，耗时分别为 25.342 秒、28.786 秒。

- 南京南：全部信息、到达屏、出发屏均显示 G100。
- 天津西：到达屏显示 G100，出发屏及全部信息显示 G97。
- 唐山：三个标签均显示 G97。
- 三站刷新后保留正确车次；车次卡片不越出大屏网格。
- 点击唐山车次后，正确进入同趟列车详情并加载停站时刻表。
  首轮验证时仍会转换为首车次；下述入口回归已覆盖保留本站车次的修复。
- 截图检查手机单列和平板双列布局，未调整设备分辨率或显示密度。

日志位于 `build/station-segments-phone-device.log`、
`build/station-segments-tablet-device.log`，截图位于 `build/verification/station-segments-*`。
初轮失败涉及测试启动准备、控件定位、路由断言及手机锁屏中断，
修正测试并在手机解锁后完整重跑通过；本轮无需修改产品代码。
