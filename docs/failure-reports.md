# 异常报告

参考本机 Read 项目的 CrashHandler / CrashReportActivity 功能，使用 CRTicket 自身的 Compose 主题独立实现报告页，不依赖 Read 的依赖注入和偏好设置。

未捕获的主线程或后台线程异常写入应用私有 `files/error-reports/latest.txt`，启动独立 `:diagnostics` 进程中的报告页，随后结束出错进程。报告包含版本、机型、Android 版本、时间、线程及异常堆栈，限制为 512000 字符，不通过 Intent 携带完整日志。页面支持选择文本、复制报告和重新启动；不会自动发送报告。

Read 的现有实现仅处理未捕获异常。本项目另加前台主线程心跳检测：前台活动存在、未连接调试器时，主线程连续八秒未响应，记录主线程堆栈并进入同一报告页。这是应用自身的无响应检测，不等同于 Android 系统判定的全部 ANR，也不能保证捕获原生崩溃、系统强杀或内存耗尽。应用在后台时不主动触发此检测。

## 验证记录

Pixel 8 Pro 验证了异常报告页的打开、复制和重新启动流程。

设置中的清理存储提供“错误日志”分类，统计私有 error-reports 目录的占用，支持单独清理及全部清理。日志不再重复计入保留的个人数据；清理后下次发生异常仍可重新生成报告。

系统应用信息中的存储入口通过 Android `manageSpaceActivity` 接入现有清理存储页。无论应用冷启动还是已打开，入口只负责导航，不执行清理；仍由用户选择分类并确认。系统按钮名称由设备系统决定。

系统存储入口验证：Pixel 8 Pro 的 CI 包通过注册信息、已有实例导航和文件及 localStorage 保留回归；冷启动直接启动已注册的 ManageStorageActivity，可显示清理存储及分类占用。系统设置的清空存储按钮实点被自动审批以可能删除全部数据为由拒绝，未执行该按钮的端到端点击，未将其计为通过。

后续修复冷启动中间页：系统入口直接建立清理存储原生页面；存储控制器等待 Web 数据层就绪后执行占用读取，不再借用设置主页面初始化。Pixel 8 Pro CI 两项回归通过，覆盖冷启动过程中无 settings-content、分类数据正常加载、已有实例导航和数据保留。获得用户明确授权后，另在应用停止状态下实点系统“清空存储空间”，确认进入清理存储和占用概览；此前实点受阻的验证限制已解除。
