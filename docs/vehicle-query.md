# 车辆查询（第一版）

- 入口：铁迷工具 → 车辆查询，原生 Compose 页面。
- 输入会去除首尾空白并转为大写。与 rail.re 一致，`^0?[GDC]\d{1,4}$`
  使用 `/train/` 查询，其余 `^[-+\w@]+$` 输入使用 `/emu/` 查询。
  支持 `380B-3626` 完整车号及 `1E`、`BF5` 等片段，不在此页提供车站查询。
- API：`https://api.rail.re/train/{keyword}` 和
  `https://api.rail.re/emu/{keyword}`。展示接口返回的全部记录，按日期倒序分组，
  同一天按时间倒序排列；不将重复担当同一车次的不同日期记录合并。
- 接口目前有返回数量限制，无分页参数；界面不能承诺覆盖车辆整个服役期。
- 卡片布局沿用到访车站统计的日期标题、16 dp 边距、8 dp 间距和自适应列宽。
  历史车次直接复用完整车次列表卡片，通过同一摘要函数获取对应日期的路路通数据，
  展示始终到站、停站数、历时、里程和均速；对应日期无记录时使用不可用占位。
- 车号卡片左侧展示源车号，右侧展示对应车型车头图，点击继续查该车号。
  车型对应表来自 https://www.china-emu.cn/Trains/ALL/ ，2026-10-21 提取，
  存于 `app/src/main/assets/vehicle-model-images.json`，图片从该网站按需加载。
  优先使用明确车号／闭合号段匹配的版本，再回退到车型默认图片。
  涉及改号、改造或缺少明确号段的条目保留默认版本；无图时不显示额外说明文字。
- 新查询取消旧请求，离开页面取消请求；支持加载状态、空结果、失败重试及输入校验。
- 搜索历史仅存于本机，按最近使用顺序去重保留 10 条，支持带动画的一键清空。
  搜索框的关闭按钮取消请求并重置结果，回到搜索历史和车头轮播初始界面。
- 轮播支持手动滑动，每 4 秒自动切换；页面未激活或 Activity 暂停时停止自动播放。
- 轮播覆盖车型目录 2026-10-21 快照的全部 307 个条目，包含样车、变体及市域车型；
  原站没有车头图片的条目保留车型名称，回退到默认图片或默认图标。
  图片仅加载当前及相邻页面，共享最多 32 张图片的缓存，不同时下载全目录。
  使用 `tools/update-vehicle-carousel.ps1` 更新目录；脚本校验页面卡片数与提取数一致。
- 车次卡片中的车号胶囊：CR400AF、CR300AF 为红色；CR400BF、CR300BF 为橙色；
  CR200 为绿色；CRH1 为黑色；CRH380A 及其他为蓝色。点击胶囊查询该卡片车次的历史用车，
  点击卡片其余区域仍打开该日期的车次详情。
- 图片别名：CR200J 使用 CR200J1-A 图片，CR200JB 使用 CR200J1-B 图片，
  CR200JC 使用 CR200J1-C 图片，CR200JD 使用 CR200J1-D 图片。
- 特别涂装精确按完整车号匹配，优先于系列：CR400BFZ0524 使用紫色胶囊及亚运版车头图，
  CR400BFC5162 使用天蓝色胶囊及冬奥版车头图；输入中的连字符不影响匹配。
  两种特别涂装分别使用独立图片键，避免与普通 CR400BF-Z / CR400BF-C 共用错误的缓存结果。
- 应用界面不显示数据来源说明，集中在 README 和本说明维护。
- 首页全局搜索采用与车辆查询页一致的输入解析，支持纯数字编号和车型片段；
  对符合车次格式的输入同时提供配车查询。车辆记录初始展示三条，支持展开全部。
  查询独立于车次和车站加载，仅在接口实际返回记录时显示车辆区域；不受首页车迷工具入口开关影响。
  入口携带原始查询词打开完整车辆查询页，支持 `train` 和 `vehicle` 参数。
- 车辆查询支持下拉刷新已提交的查询，保留当前卡片与滚动位置。
  初始搜索历史界面不发起刷新，刷新不重复添加搜索历史；刷新失败时保留已有结果并允许重试。
- 车型详情的逐项核对结果和新增规则见 [图片核对清单](vehicle-artwork-audit.md)。
- 第一版提供英文默认文案及简体中文，其他语言暂使用英文回退。

## 车辆实拍照片

- 完整车号或包含车型与车号的简称，在历史记录数量上方按需加载下关站照片。
- 去除 CR / CRH 前缀及分隔符后核对车辆身份；只有照片结果与已有配属记录均不产生车辆歧义时显示。重联中的不同车辆也视为多个候选。
- 完整车型车号优先使用下关站对应的精确车号检索，未命中时回退到末尾四位车号检索；完整身份匹配后无需读取无关分页。纯数字如 5033 仍需核对全部候选，超过五页、分页无法确认或结果不唯一时不展示。
- 即使 rail.re 没有历史记录，仍可显示唯一匹配的照片；照片失败、超时或解码失败时隐藏，不影响记录查询。查询运行车次时不显示实拍照片。
- 点击照片查看拍摄日期、配属、线路、城市、车次、作者和原始详情链接。空字段或值 0 显示未知。当前版本仅显示首张匹配照片。
- 原站使用 GB2312 页面编码（按 GB18030 兼容读取），HTTP 只对 www.xiaguanzhan.com 放行，不放开 WebView 混合内容；请求不跟随重定向，响应上限 8 MiB，照片按显示尺寸采样。
- 照片版权归拍摄者；下关站要求交流转载注明出处和作者，禁止商业使用和短视频发布。出处及作者在详情弹窗中保留，图片不打包进 APK。

来源：http://www.xiaguanzhan.com/

验证：2026-11-01，四项照片解析及匹配单元测试通过；Pixel 8 Pro 的独立 CI 包通过 `VehiclePhotoDeviceTest`。真实请求验证 400BFZ0524 在空历史下可加载照片、5033 无法唯一匹配时隐藏，并验证查询页图片及出处作者弹窗；已核对两张截图。首次 HTTP 响应头读取超时，改用原站分页 GET 并设置 20 秒读取超时后通过。

## 照片缓存与大屏布局

成功加载的照片保存在应用私有 `cache/vehicle-photos`，按图片地址去重，最多 32 MiB；再次查看时复用图片。
可在清理存储页单独清理“车辆照片缓存”或随全部清理删除，不影响配属历史和其他个人数据。
清理前已启动的请求不能在完成后写回缓存。完整车号的照片对应关系与拍摄信息也缓存 24 小时，和图片共用 32 MiB 上限，并随照片缓存一并清理。缓存命中时无需先连接原站。

照片区域实际可用宽度达到 720 dp 时，采用左侧照片、右侧拍摄信息和出处链接的布局，
图片最高 280 dp，直接展示信息且不设置整张卡片点击弹窗。窄屏仍使用照片卡片与点击详情。
布局依据当前内容宽度自适应，不修改设备显示参数。

2026-11-01 在真实 Pixel Tablet 上通过照片与缓存专项：照片左侧、拍摄信息右侧，无需点击即可查看；已核对截图，图片高度不超过 280 dp，未调整设备显示参数。专项同时验证缓存占用、单项删除和旧请求不可写回。

## 查询返回与加载速度

同一车辆查询页面内维护逐层查询记录。系统返回与标题返回按钮优先恢复上一条查询、
已有配属记录、车次摘要及列表滚动状态；退回最初的车辆搜索页后，再返回外层首页。
例如 C3896 → CRH2A-2001 → 2001，返回依次恢复 CRH2A-2001、C3896、车辆搜索页、首页。
下拉刷新和失败重试不新增返回层级，清空按钮仍直接重置到搜索初始界面。

下关站一直使用 HTTP 直连。完整车号照片与 rail.re 历史请求并行，照片不等待历史完成；
后续历史若出现车辆歧义，则隐藏照片。完整车号别名复用同一份本地图片和拍摄信息。
纯数字仍等待历史核对，避免把多辆车中的第一张照片当作唯一命中。

2026-11-01，Pixel 8 Pro 的 CI 包通过逐层返回和照片专项两项设备测试，
五项照片解析与精确检索单元测试通过。本次首次照片读取 9622 ms，
以完整车号别名再次读取本地缓存 61 ms；耗时受设备与上游网络影响。
日志：`logs/vehicle-back-photo-speed-validation.log`。
