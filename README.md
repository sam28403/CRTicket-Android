# CRTicket-Android — 手机独立版

后端逻辑已内置 APK。手机通过 Android 原生网络层直接连接 12306 和路路通，查询、解析、缓存及车票数据处理都在手机内完成。无需电脑、远端后端、端口映射或额外的运行环境。

网页功能及依赖已同步原项目 `ece5529`（Version 261013）：里程改为在车票表单中填写，保存时直接存储并防止重复提交；路路通版本请求与数据包下载分别计时，单包最多 60 秒、整轮下载最多 90 秒，失败后可立即重试；查询页、地图及数据管理文案同步精简，Vue 与锁文件同步更新。Android 原生下载层同步支持 60 秒数据包请求，同时保留本机时刻表缓存及原生后台余票监控。原生 Expressive 首页、车站位置地图、在线／离线查询切换、沿途换号车次、补登／编辑记录、列车追踪及到站提醒均保留。Android 版继续排除电脑端登录、调试页面及 GitHub Pages 部署配置。原项目文件校验基线已更新至 199 个文件，包含新版截图路径，排除依赖、构建产物和运行中的数据库。

## 使用

安装 `app/build/outputs/apk/debug/app-debug.apk` 即可。应用默认使用“默认用户”，可在“数据管理”中修改用户名；没有登录、注册或后端地址设置，顶部实现说明栏已移除。

启动后先显示原生 Material 3 Expressive 首页，采用 Android 设置风格的大圆角分组及紧凑选单。标题使用项目内的 Google Sans Rounded Regular 字体，左侧保留圆形 `Picture1.png` 图标；标题下方提供搜索输入框，暂不执行搜索或筛选。第一组依次提供车票生成、历史记录、余票监控、车次查询、车次列表及车站大屏，均进入现有业务页面；第二组提供设置（现有数据管理）与关于，组内间隔为 2dp。关于页参考 Read 项目的中央图标、应用名称、版本及底部圆形按钮布局，显示 CRTicket 当前应用图标与 APK 版本，GitHub 按钮打开 `https://github.com/sam28403/CRTicket`。首页和关于页支持系统动态配色及现有亮／暗色偏好；业务页面仍沿用原界面。系统返回逐级回到首页，在首页返回退出。通知入口直接进入对应业务页面，页面恢复保留当前导航位置。

- 车票制作、历史增删改、头像、统计、地图、PNG/PDF/Excel 导出和 JSON 备份都使用手机本机数据。
- 车票表单的“里程”用于统计，保存前必须填写非负数字；点击“存储到本机”直接保存，不再弹出里程输入对话框。车票图片导出沿用原有逻辑。
- 余票与在线车次查询由手机直接请求 12306。
- 车次查询可切换在线或路路通离线来源；离线组合车次可按沿途任一完整车次号查询，同名记录有歧义时需从车次列表选择完整记录。切换在线来源时，范围外日期自动改为今天。
- 车站大屏新增“地图”标签。Android 使用本地 Leaflet 组件显示车站标记并加载 OpenStreetMap HOT 瓦片，保留缩放、拖动和地图署名；地图需要联网，瓦片加载失败时提示检查网络。
- “数据管理 → 到站提醒”默认关闭。用户开启时说明后台位置用途，依次申请精确定位、“始终允许”定位及“到站提醒”通知。Android 11 及以上需在系统设置的“权限 → 位置信息”中手动选择“始终允许”。返回应用后自动继续授权及围栏注册；系统授权导致进程重建时恢复已经确认的开启请求。拒绝授权不影响其他功能，关闭会移除围栏、被动位置订阅和未完成的位置请求。
- 到站提醒使用 WGS84 坐标和 300 米进入围栏，显示“欢迎到访XX站 / 点按查看当前车站大屏”，无需停留 30 秒；位置判定不额外扩大 300 米边界。点击通知无论应用已打开或关闭，都打开对应站点当天的大屏。同站 30 分钟内不重复提醒，邻近站同时触发时只提醒最近的站。系统地理围栏可能延迟几分钟，不能保证高速经过、室内弱定位或系统限制下及时触发。
- 到站提醒需要可用的 Google Play 服务和系统定位。全站清单在网页构建时覆盖坐标表全部 28,429 个名称，按相同坐标合并为 11,213 个站点，保留全部别名，优先官方站名和短中文名，包括香港和老挝。系统上限为 100 个围栏，因此动态注册最近 99 个站点并保留一个移动范围围栏；离开该范围时重新选择站点。初始化或缺少有效围栏触发位置时，最多请求 15 秒的单次平衡功耗定位。平时仅以 PASSIVE 模式接收系统或其他应用已经取得的位置，最短交付间隔 2 分钟、移动至少 1 公里，每次交付也匹配全坐标表；不再主动请求周期定位。系统围栏本身仍需要后台位置，手机仍可能显示位置访问记录，不能保证完全没有位置提示。应用不上传位置到应用服务器，不保存出行轨迹；手机重启、应用升级或定位重新开启后尝试恢复，强行停止应用后需手动打开应用恢复。
- 车站大屏由手机直接查询 12306，当天无结果或查询失败时使用本机路路通时刻表，按本站到发日反推始发日期并筛选开行规则。支持全部、进站和出站视图、当前时间定位及手机虚拟列表；查询缓存一分钟并合并并发请求。站名可跳转车站大屏，车次可跳转相应始发日期的在线或离线详情。检票口、出站口和正晚点仅在上游提供时显示，离线信息请以车站公告为准。
- 列车列表及离线时刻表由手机下载路路通数据包，在 Web Worker 中解析，并保存到本机 IndexedDB。后续可使用已下载数据，联网时检查更新。
- 车次列表和车站大屏使用浏览器原生触摸滚动，快速划动后保留惯性，和车次时刻表结果一样自然滑动。继续按需渲染虚拟行，返回车次列表时保留滚动位置；手动浏览大屏暂停时间跟随，列表顶部仍支持下拉刷新。
- 经典与高对比度的“跟随系统”直接读取 Android 夜间模式，并在系统切换或回到前台时更新；手动亮色、暗色选择保持独立。
- 原有手机离线车票记录保留。卸载应用或清除应用数据会清除记录和时刻表缓存，请通过导出备份保存重要数据。
- 文件导入、保存由 Android 系统文件选择器处理，无需存储权限；单文件导出上限 20MB。
- 设置中的“导出 Excel”“导出备份”“导入备份”仅显示操作名称。导出 Excel 将车票整理为电子表格；导出备份保存 JSON 文件，便于恢复和迁移；导入备份从 JSON 恢复车票，保留现有记录并自动略过相同记录。
- “设置 → 到站检测”提供独立详情页，展示随系统动态配色的列车／车站矢量形变动画、启用开关及权限入口。入口说明固定为“接受到访车站的通知”，开启状态由开关表达；异常状态和重新开启入口在详情页显示。从详情页进入权限管理后，返回先回到站检测，再回设置。动画仅在页面可见且应用处于前台时播放。
- 历史记录使用原生 Expressive 纵向卡片，顶部显示票号，路线下方显示日期时间，底部左侧显示票价、右侧显示座位号与席别。保留日期／票价双向排序；下拉刷新复用车次列表的原生变形指示器，仅重新读取本机记录。补登／编辑进入第三级原生页面，提供站名／拼音建议、日期时间选择、席别、积分、空调及背景设置；删除使用原生确认框。宽屏沿用左侧导航、右侧详情布局，折叠区域变化时保留编辑草稿并避开折痕。
- 首页左上角产品图标保持静态显示。关于页 Logo 点击时保留震动，并增加花瓣与圆形之间的形变、缩放及回弹动画，原有连续点击彩蛋保留。形变使用 AndroidX Material Shapes 与 Compose 原生绘制，无需下载动画素材。
- 支持 Expressive 样式下拉刷新：滑到页面顶部，松手后再次下拉，释放手指即刷新当前页面。表格、列表等内部滚动区域也遵循相同操作。没有起点区域、长距离或等待时间要求，仅保留触摸抖动容差；从中部滑回顶部的那次手势不会刷新。普通点击、横向滑动、向上滑动、多指操作、地图拖动、输入控件及打开的弹窗／选择器保留原有操作，下拉后会抑制该次误点击，拉回起点可取消刷新。Android 使用原生 Material 3 Expressive 变形加载指示器，浏览器使用网页动画；说明规则不常驻页面。当前网址、已保存记录、离线缓存和原生列车追踪保留，未保存的表单输入及前台余票监控会随页面重载重置。
- 余票监控在开始时申请系统通知权限，有票或余票变化时发送“余票提醒”通知；点击通知可返回监控页面。通知被关闭时可前往系统设置开启，未授权时保留页面内提醒。监控仍采用前台轮询，手机锁屏或应用进入后台可能延迟，没有持续后台服务。
- 车次详情标题右侧提供 primary「追踪」按钮，申请独立的“列车追踪”通知权限后，通过 Android 前台服务在离开页面后继续追踪。一次追踪一趟列车，追踪其他车次会替换当前追踪；页面按钮或通知中的“停止追踪”均可结束。
- 列车追踪统一使用北京时间和查询的始发日期，处理跨午夜及累计跨日数。通知标题统一为“车次 · 起点→终点”，正文另起一行显示“前方到站：XX”及剩余时间；停站时正文分两行显示“当前到站：XX，XhXXm后出发”和“前方到站：XX，预计到达：HH:mm”；预计到达统一使用北京时间，跨日时补充月日。终到时显示终点站名。车次和正文保持加粗，不显示推算说明等附加文字。系统模板控制字号，自定义大字布局会失去 Live Updates 资格，因此保留系统样式。运行期间胶囊倒计时表示距离下一站到达的时间；停站时胶囊显示当前站名，四字以内完整显示，较长站名在亮屏时每 3 秒切换四字窗口以展示全名，熄屏时停止快速轮播；系统胶囊不提供自定义走马灯接口，最终可见宽度由系统控制。未发车时表示距离发车的时间，大于 24 小时显示 `XXdXXh`，1–24 小时显示 `XXhXXm`（恰好 24 小时显示 `24h0m`），不足 1 小时显示 `XXm`。到达终点后结束后台服务：在终到前已开启追踪的车次，从时刻表终到时间起保留“已达终点”胶囊及到达通知 30 分钟，之后自动退出追踪；终到后才点击追踪的车次，从本次开启时起保留 3 分钟。自动退出会移除通知和胶囊，并清除本机追踪状态；服务恢复和页面重载不会重置期限，手动停止或清除仍可提前结束。点击通知可返回对应车次及始发日期。
- 列车追踪恢复原来的“列车追踪”通知渠道及默认优先级，沿用该渠道的系统设置；不再使用“列车追踪（静默）”渠道。倒计时更新继续使用相同通知 ID，并保留仅首次提醒设置，不影响余票提醒。
- 待发车、运行中、当前停站、终到分别使用时钟、运行列车、站点定位、完成勾选四种状态图标，设置系统小图标、大图标，并在进度样式中设置进度标记，供胶囊、AOD 和通知栏显示。Pixel AOD 左侧保留系统应用徽标，右侧显示对应状态大图标；左侧应用标识属于系统通知模板，公开 API 无法移除。通知标题根据 12306 各站车次号在到达换号站时切换，旅程标识及点击跳转仍保留原查询车次；旧追踪数据未带站点车次号时沿用原车次，离线库仅提供组合车次号时保持组合号，不推断换号点。Pixel 实机查询 G97/100 已验证天津西站由 G100 切换为 G97。
- 首次前台服务通知请求立即显示；后续更新使用独立的通知更新抑制规则，保留默认渠道和 Live Updates 资格，不创建分组摘要或重复通知卡片。AOD 的实际提醒行为通过 Pixel 8 Pro 的 DozeLog 和截图进行对照验证。
- Android 16 在运行等状态使用系统进度样式，停站时使用支持 Live Updates 的系统长文本样式以完整显示到发信息，Android 16 QPR1（API 36.1）及以上从用户开启追踪时即申请 Live Updates，未发车的列车也申请左上角胶囊，不再限制为发车前一小时。实际展示由系统、通知设置及设备厂商决定。旧系统显示持续更新的常驻通知，按分钟和到发边界更新，恢复亮屏时重新计算。系统深度休眠或强行停止应用可能延迟或中断更新，重启手机后需手动开启追踪。
- **追踪状态按时刻表推算，不代表实际定位或实时运行情况，不包含晚点、临时停运等信息。** 详情页注明这一点；缺少到发时间或无效跨日数据的车次无法开始追踪。

12306 或路路通上游服务的验证、限流、接口调整及网络故障会影响在线查询；应用会展示错误。缓存数据的版本会在查询结果中显示，离线参考不能代替 12306 实时开行和余票信息。

最低 Android 8.0（API 26），设备需要支持现代 JavaScript 的 Android System WebView / Chrome。

## 模块

- `app/src/main/java/cc/samlab/ticket/network/PhoneHttp.kt`：Android 原生 HTTP、Cookie、取消请求与二进制分块传输。
- `app/src/main/java/cc/samlab/ticket/network/UpstreamPolicy.kt`：只接受所需的 12306、路路通数据地址。
- `web/src/android/railway`：车次、余票、列车列表、路路通二进制解析、IndexedDB 缓存和解析 Worker。
- `web/src/android/localApi.js`：默认用户和本机车票操作。
- `app/src/main/java/cc/samlab/ticket/arrival`：到站提醒权限、附近车站围栏、恢复、去重和通知跳转。
- `web/src/components/StationArrivalCard.vue`：到站提醒开关、权限和定位状态。
- `app/src/main/java/cc/samlab/ticket/tracking`：列车时间轴、通知、后台服务、状态持久化和 WebView 桥接。
- `web/src/components/TrainTrackingButton.vue` 与 `web/src/android/trainTracking.js`：车次追踪按钮和 Android 通知接口。

保留前一版启动优化：页面、图表和导出库按需加载；手机票面实时等比显示；字体使用精简 WOFF2；静态资源可缓存，升级清理资源缓存时保留本机数据。

## 构建和检查

版本名称格式为 `<x.y.z>-<当前提交的至少 7 位短哈希>-<原项目版本日期>`。
`x.y.z` 由你手动修改根目录 `gradle.properties` 中的 `crticket.version`，默认 `0.3.3`，不会随提交自动变化。
日期在构建时自动读取 `crticket.upstreamMainView` 指向的原项目 `MainView.vue` 中的 `<h3>Version 260930</h3>`。
默认文件为 `C:/Users/SAM-LAB/WebstormProjects/CRTicket/src/views/MainView.vue`；换电脑时可修改该路径，原文件更新后构建缓存会自动刷新。
文件缺失或没有唯一的版本日期时构建会报错，不会使用旧日期或本机日期。
Android 内部 `versionCode` 从 7 起随提交次数递增，支持覆盖升级此前的版本；它不影响手动设置的 `x.y.z`。
尚无提交时哈希标记为 `uncommitted`；构建需要完整 Git 历史。
可运行 `.\gradlew.bat :app:printAndroidVersion` 查看实际版本，或运行 `tools/verify-versioning.ps1` 验证版本配置、日期更新和缓存刷新。

网页资源已生成，Android Studio 可直接运行 app。修改网页副本后重新构建：

```powershell
cd web
node --version # 需要 Node.js >=22.12.0
npm ci # 首次安装依赖时使用
npm run test:android
npm run build
cd ..
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

使用项目原有 AGP 9.5.0-alpha09、Gradle 9.6.0、SDK 37 和 Java 25 工具链。Kotlin 编译器 2.5.0-Beta1，运行时 2.2.10。

`tools/smoke-web.cjs` 检查手机版布局、本机历史和四种导出，需要 Playwright 和 Chrome。

`node tools/smoke-home.cjs` 使用模拟 Android 桥接检查首页及关于页路由与原生显示状态、系统返回逻辑、弹窗优先关闭、直接入口、刷新恢复、八个浏览器备用入口及 GitHub 目标链接。该检查不验证原生 Compose 布局的实际显示效果。`ExpressiveHomeTest` 用于实机检查搜索输入不筛选、全部八个入口、关于页图标与版本、页面返回与系统返回、输入保留和键盘仅在点按搜索框时显示，并保存首页、键盘及关于页截图。

首页字体、八个入口、搜索框与关于页已于 2026-10-14 在 Pixel 8 Pro 上通过上述两项实机测试，并检查页面截图。沿用设备当前显示缩放（544dpi）与字体缩放（1.0），未改变系统显示设置。

`node tools/smoke-station.cjs` 使用模拟 Android 网络接口检查车站大屏在 320–1200px 下的布局、标签筛选、虚拟列表、站名和车次跳转及查询缓存；不验证上游当天的实际开行信息。

`node tools/smoke-train-source.cjs` 使用模拟 Android 网络接口与离线数据包验证查询来源切换、换号车次、请求取消、在线日期范围、完整离线记录恢复、页面查询缓存及手机布局。车站冒烟测试同时检查本地地图标记和瓦片加载，地图瓦片使用测试图片。

`node tools/smoke-pull-refresh.cjs` 使用真实浏览器触屏事件检查页面及内部列表滑到顶部后再次短下拉刷新、地图／控件／弹窗避让、拉回取消、重复触发保护、页面重载及浏览器动画。`PullRefreshTest` 在 Android 实机验证滑到顶部后再次短下拉、原生 Expressive 指示器、松手后刷新、当前网址与保存记录保留，以及刷新不改变原生列车追踪。`pullRefreshGesture.test.js` 验证手势方向、触摸抖动、再次下拉及多指边界。

`node tools/smoke-list-scroll.cjs` 检查两张实际虚拟表格的触摸事件不被 JavaScript 阻止、列表滚动、虚拟行数量、返回位置恢复及列表顶部下拉刷新。`ListScrollTest` 在 Pixel 实机验证快速划动的滚动距离超过手指移动距离，以及大屏暂停跟随、虚拟渲染和避免误刷新。

`node tools/smoke-station-arrival.cjs` 检查到站提醒开关、权限拒绝、页面重载、关闭和不支持设备的提示及手机布局。`ArrivalPolicyTest` 验证距离、围栏数量、动态覆盖和去重；`StationArrivalNotificationTest` 是真机通知文案及站点目标隔离测试，不读取实际位置。实际到站时延和耗电需在允许定位后实机观察，模拟测试不代表实际耗电测量。

`node tools/smoke-train-tracking.cjs` 使用模拟 Android 接口检查追踪按钮在 320–1200px 的布局、拒绝通知权限、启停、页面重载恢复和通知停止后的状态同步；不验证真机系统通知的展示效果。

`TrainTrackingNotificationTest` 验证通知图标、渠道、停站长文本与胶囊资格；`TrainStationNotificationTest` 验证停站文案、跨日北京时间及到发边界，`TrainStationChipSceneTest` 在真机验证五字站名轮播并截图检查完整到发信息；`TrainTrackingAodProbeTest` 在真机上观察 85 秒 AOD 倒计时并记录 DozeLog 和截图；`TrainTrackingIconSceneTest` 验证四种状态图标及模拟换号；`TrainRailwayCodeProbeTest` 从手机查询 G97/100，验证天津西实际站点号码变化。设备观察测试临时使用调试时刻表，结束后恢复原追踪；不修改设备时间或全局 AOD 设置。

`TrainTrackingSessionTest` 验证终到前追踪保留 30 分钟、终到后开启保留 3 分钟及时间边界。`TrainTrackingExpiryTest` 在真机检查持久化期限、系统通知超时清除、旧会话回调隔离、手动停止及旧记录清理；通知清除路径将测试会话临时缩短到 2 秒，正式应用仍使用 30 分钟／3 分钟。

`PhoneBackendTest` 是 Android 真机测试，验证在没有电脑后端与端口映射的情况下，手机加载路路通数据并访问 12306。生成测试包：

```powershell
.\gradlew.bat :app:assembleDebugAndroidTest
```

字体工具位于 `tools/optimize-fonts.py`，只处理当前 Android 项目的副本。所有原网页文件均保持只读，可执行下列校验：
